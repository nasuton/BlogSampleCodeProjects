# 03. 日常の開発フロー

すべて **VS Code を Dev Container で開いた状態** (左下に `Dev Container: SPFx (Node 22)` と表示) で行います。

## コンテナを開く / 閉じる

| 操作 | 方法 |
| ---- | ---- |
| 開く | フォルダーを VS Code で開く → `F1` → **Dev Containers: Reopen in Container** |
| 閉じる | `F1` → **Dev Containers: Reopen Folder Locally** (コンテナは `shutdownAction: stopCompose` で自動停止) |
| 設定を変えた後 | `F1` → **Dev Containers: Rebuild Container** (`Dockerfile` / `docker-compose.yml` / `devcontainer.json` 変更時) |
| `.env` を変えた後 | 再作成不要。ターミナルを閉じて新しく開くだけ |

## 開発サーバー (serve)

1. `Ctrl+Shift+B` → **SPFx: serve**
   (またはターミナルで `npx heft start --clean --nobrowser`)
2. ターミナル先頭に表示される `Workbench URL:` をブラウザで開く
   ```
   https://<テナント>.sharepoint.com/_layouts/workbench.aspx?debugManifestsFile=https%3A%2F%2Flocalhost%3A4321%2Ftemp%2Fbuild%2Fmanifests.js&debug=true&noredir=true
   ```
3. **+** → ローカル セクションからコンポーネントを追加
4. `src/` を編集して保存 → 自動で再ビルド (`webpack compiled successfully`) → ブラウザを再読み込み
5. 停止は serve ターミナルで `Ctrl+C`

> ポート 4321 は VS Code が自動でホストへフォワードします (「ポート」タブで確認可)。
> **複数プロジェクトを同時に開いている場合、serve は 1 つずつ**。2 つ目は別ポート (例 4322) にフォワードされますが、
> マニフェスト URL は `localhost:4321` 固定なので読み込めません。

### 実ページでデバッグしたい場合

ワークベンチではなく実際のサイトページに同じクエリ文字列を付けます。

```
https://<テナント>.sharepoint.com/sites/<サイト>/SitePages/<ページ>.aspx?debugManifestsFile=https%3A%2F%2Flocalhost%3A4321%2Ftemp%2Fbuild%2Fmanifests.js&debug=true&noredir=true
```

## ブレークポイントでデバッグ (F5)

serve を起動した状態で `F5` (**SPFx: Hosted Workbench (Edge)**) → ホスト側で Edge が開き、`src/**/*.ts(x)` に置いたブレークポイントで停止します。
詳細は [06_VSCodeデバッグ手順.md](06_VSCodeデバッグ手順.md)。

## コンポーネントの追加

```bash
# コンテナ内ターミナルで (対話式)
yo @microsoft/sharepoint
```

既存ソリューションへの追加なので "Which type of client-side component to create?" 以降だけ聞かれます。

## ビルドとパッケージ

| 目的 | タスク / コマンド | 出力 |
| ---- | ---- | ---- |
| 本番ビルド + パッケージ | **SPFx: build (production)** / `npm run build` | `sharepoint/solution/<solution>.sppkg` |
| クリーン | **SPFx: clean** / `npm run clean` | — |
| Lint | `npx heft lint` | — |
| テスト | `npx heft test` | `jest-output/` |

`.sppkg` はホスト側フォルダーにも出力されるので、そのままアプリ カタログへアップロードできます。

### バージョンアップ時

`config/package-solution.json` の `solution.version` を上げてから `npm run build`。

## パッケージの追加

```bash
npm install <package>          # コンテナ内で実行 (node_modules は volume 内)
```

`package.json` / `package-lock.json` はホスト側に反映されるので git 管理できます。
他のメンバーがクローンした場合は Reopen in Container 時の `postCreateCommand` で自動的に `npm install` されます。

## 証明書の更新

開発用証明書の有効期限は **1 年**。期限切れになったら:

1. **SPFx: trust dev cert** タスク (または `trust-dev-cert.sh`)
2. 出力された `certs\rushstack-serve.cer` を再度ホストの「信頼されたルート証明機関」へインポート
3. ブラウザを再起動

## 環境のリセット

```powershell
# ホスト側 PowerShell で
docker compose down -v      # node_modules / 証明書 volume を削除 (証明書は再インポートが必要になる)
```

その後 **Rebuild Container** で作り直し。
