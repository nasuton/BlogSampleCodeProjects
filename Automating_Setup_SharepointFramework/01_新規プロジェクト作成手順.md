# 01. 新規プロジェクト作成手順

## 前提

- Docker Desktop がインストール済み (スクリプトは未起動なら自動で起動して待機します)
- VS Code に **Dev Containers** 拡張 (`ms-vscode-remote.remote-containers`) がインストール済み
- Microsoft 365 開発者テナント (ワークベンチ動作確認用)

---

## A. スクリプトで作成する (推奨)

`Doc\New-SpfxProject.ps1` がテンプレート配置 → イメージビルド → `yo @microsoft/sharepoint` 実行 → 後処理までを自動化します。

#### A-1. 対話形式で作成する (bat ダブルクリック / 引数なし)

`New-SpfxProject.bat` をダブルクリック (または `.\New-SpfxProject.ps1` を引数なしで実行) すると、以下を順に聞かれます。番号を入力、または Enter で `*` の既定値になります。

1. **コンポーネントの種類**: `webpart` / `extension` / `library` / `adaptiveCardExtension`
2. **拡張機能の種類** (extension のときのみ): `ApplicationCustomizer` / `FieldCustomizer` / `ListViewCommandSet` / `FormCustomizer` / `SearchQueryModifier`
3. **フレームワーク** (webpart / ApplicationCustomizer / FieldCustomizer / FormCustomizer のときのみ): `react` / `none` / `minimal` (minimal は webpart のみ)
4. 作成先フォルダー、ソリューション名、コンポーネント名 (フォルダー名から候補を提示)、テナントドメイン
5. 最後に内容を表示して `Y/n` で確認

引数で渡した項目はスキップされるので、`-ComponentType extension` だけ渡して残りを対話で決める、といった使い方もできます。

#### A-2. 引数で全部指定する

```powershell
cd D:\work\SPFx\SampleSPFx\Doc

.\New-SpfxProject.ps1 `
  -Path          D:\work\SPFx\MyProject `      # 作成先 (空フォルダーまたは未作成)
  -SolutionName  my-project `                  # package.json の name / .sppkg 名 (小文字ケバブケース)
  -ComponentName MyWebPart `                   # 最初のコンポーネント名 (PascalCase)
  -ComponentType webpart `                     # 種類 (省略時は対話で選択)
  -Framework     react `                       # フレームワーク (省略時は対話で選択)
  -TenantDomain  contoso.sharepoint.com `      # 任意: .env に書き込まれ Workbench URL 表示に使われる
  -SkipInstall `                               # 任意: npm install を Dev Container 起動時に任せる
  -NonInteractive                              # 任意: 一切プロンプトを出さず既定値で進める
```

拡張機能の例:

```powershell
.\New-SpfxProject.ps1 -Path D:\work\SPFx\MyCmd -SolutionName my-cmd -ComponentName MyCommand `
  -ComponentType extension -ExtensionType ListViewCommandSet -NonInteractive
```

bat (コマンド プロンプト / ダブルクリック) から呼ぶ場合は同梱の `New-SpfxProject.bat` に同じ引数を渡します。

```bat
D:\work\SPFx\SampleSPFx\Doc\New-SpfxProject.bat -Path D:\work\SPFx\MyProject -SolutionName my-project -ComponentName MyWebPart -TenantDomain contoso.sharepoint.com -SkipInstall
```

> ⚠️ `docker : failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine` と出る場合は Docker Desktop が起動していません → [05 記録 9](05_構築時に躓いた内容と対処記録.md#記録-9-bat-から-ps1-を呼ぶと-docker-api-に接続できない)

### パラメーター

| パラメーター | 既定値 | 説明 |
| ---- | ---- | ---- |
| `-Path` | (対話で入力) | プロジェクトフォルダー |
| `-SolutionName` | (対話で入力) | ソリューション名 |
| `-ComponentName` | (対話で入力) | コンポーネント名 |
| `-ComponentType` | (対話で選択 / 既定 `webpart`) | `webpart` / `extension` / `library` / `adaptiveCardExtension` |
| `-Framework` | (対話で選択 / 既定 `react`) | `react` / `none` / `minimal` (webpart・ApplicationCustomizer・FieldCustomizer・FormCustomizer で有効。それ以外は無視) |
| `-ExtensionType` | (対話で選択 / 既定 `ApplicationCustomizer`) | `-ComponentType extension` のときの種類 |
| `-TenantDomain` | (対話で入力 / 空欄可) | `.env` の `SPFX_SERVE_TENANT_DOMAIN` |
| `-SkipInstall` | off | `npm install` を省略 (Dev Container の `postCreateCommand` で実行される) |
| `-SkipBuild` | off | `docker compose build` を省略 (イメージが既にある場合) |
| `-NonInteractive` | off | プロンプトを出さない。未指定の選択項目は既定値、`-Path` 等が無ければエラー |
| `-LogPath` | `Doc\logs\New-SpfxProject_<日時>.log` | 実行ログの出力先。画面に出た内容 (docker の出力・エラー詳細含む) がすべて記録される |

エラーが出て内容が追えない場合は `Doc\logs\` の最新ログを開いてください。末尾に `==== エラー ====` ブロック (メッセージ・発生行・スタックトレース) が記録されています。

### スクリプト完了後

1. `code D:\work\SPFx\MyProject`
2. `F1` → **Dev Containers: Reopen in Container**
   - 初回はイメージビルド後、`postCreateCommand` で `npm install` と開発用証明書生成 (`./certs`) が走る (数分)
3. **初回のみ** `certs\rushstack-serve.cer` をダブルクリック → 証明書のインストール → 現在のユーザー (またはローカル コンピューター) → **信頼されたルート証明機関**
   - ブラウザを一度完全終了して再起動
   - ⚠️ これを飛ばすとワークベンチで「デバッグ マニフェストを読み込み中にエラー」になる → [05 記録 7](05_構築時に躓いた内容と対処記録.md#記録-7-ワークベンチでデバッグ-マニフェストを読み込み中にエラー-)
4. `Ctrl+Shift+B` (タスク **SPFx: serve**) → ターミナル先頭に `Workbench URL: https://...` が表示される
   - ⚠️ `Placeholder {tenantdomain} ... SPFX_SERVE_TENANT_DOMAIN is not set` と出る場合 → [05 記録 6](05_構築時に躓いた内容と対処記録.md#記録-6-env-を作ったのに-tenantdomain-の警告が消えない-)
5. ブラウザで `https://localhost:4321/temp/build/manifests.js` を直接開き、警告なしで JS が表示されることを確認
6. Workbench URL をブラウザで開き、**+** → ローカル セクションに自分の Web パーツが出れば成功

## B. 手動で作成する

スクリプトが使えない場合や、仕組みを理解したい場合の手順です。

### 1. フォルダーを作りテンプレートをコピー

```powershell
New-Item -ItemType Directory D:\work\SPFx\MyProject
Copy-Item -Recurse -Force D:\work\SPFx\SampleSPFx\Doc\template\* D:\work\SPFx\MyProject
cd D:\work\SPFx\MyProject
```

> `template\` 配下の隠しファイル (`.devcontainer`, `.vscode`, `.dockerignore` など) もコピーされていることを確認。

### 2. シェルスクリプトを LF に統一

Windows のエディターや git の設定で CRLF になっていると `exec: no such file or directory` で起動に失敗します。

```powershell
Get-ChildItem docker\*.sh | ForEach-Object {
  $c = (Get-Content $_.FullName -Raw) -replace "`r`n", "`n"
  [IO.File]::WriteAllText($_.FullName, $c, (New-Object Text.UTF8Encoding $false))
}
```

### 3. `.env` を作成

```powershell
Copy-Item .env.example .env
# SPFX_SERVE_TENANT_DOMAIN=<テナント名>.sharepoint.com に書き換える
```

### 4. イメージをビルドし、yo でソリューションを生成

```powershell
docker compose build
docker compose run --rm spfx yo @microsoft/sharepoint `
  --solution-name my-project --component-type webpart --component-name MyWebPart `
  --framework react --skip-install --no-insight
```

対話式で選びたい場合は引数なしで `docker compose run --rm spfx yo @microsoft/sharepoint`。

### 5. 生成物をプロジェクト直下に展開

yo は `my-project/` サブフォルダーに生成するため、ルートへ移動します。
`.vscode` はテンプレートのもの (`tasks.json` / `settings.json` / `launch.json`) を使うので、yo 生成の `.vscode` は捨てます。

```powershell
Get-ChildItem .\my-project -Force | Where-Object Name -ne '.vscode' | Move-Item -Destination . -Force
Remove-Item .\my-project -Recurse -Force
Remove-Item .\node_modules -Force -ErrorAction SilentlyContinue   # 空フォルダーが残っていたら削除
Add-Content .gitignore "`n# Docker / local`n.env`ncerts/`n"
```

### 6. VS Code で開く

以降は **A. スクリプト完了後** の手順 1〜5 と同じです。

## 既存の SPFx プロジェクトに Dev Containers を後付けする

1. `template\*` をプロジェクトルートへコピー (既存の `.vscode\settings.json` は `typescript.tsdk` を `node_modules/typescript/lib` に修正)
2. `docker\*.sh` を LF に変換 (上記 B-2)
3. `.env` を作成、`.gitignore` に `.env` と `certs/` を追加
4. `package.json` の `engines.node` が Node 22 を許容しているか確認 (SPFx 1.21 以降)。古い SPFx (1.20 以前 = Node 18) の場合は `Dockerfile` の `FROM node:22-...` を `node:18-...` に変更し、`gulp serve --nobrowser` を使う
5. **Reopen in Container**
