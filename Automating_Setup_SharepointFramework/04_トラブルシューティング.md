## 起動・ビルド系

### `failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine`

Docker Desktop が起動していない。起動して `docker info` が通ることを確認。

### `exec /usr/local/bin/entrypoint.sh: no such file or directory`

`docker/*.sh` の改行が **CRLF** になっている (shebang 行の `\r` が原因)。

```powershell
Get-ChildItem docker\*.sh | ForEach-Object {
  $c = (Get-Content $_.FullName -Raw) -replace "`r`n", "`n"
  [IO.File]::WriteAllText($_.FullName, $c, (New-Object Text.UTF8Encoding $false))
}
```

`.gitattributes` で `*.sh text eol=lf` を指定済み。VS Code の右下で `CRLF` になっていたら `LF` に切替。

### `npm install` で `EACCES` / `The operation was rejected by your operating system`

名前付き volume (`node_modules`) が root 所有。`entrypoint.sh` が起動時に `chown` するので通常発生しないが、
古いイメージで作られた volume が残っている場合は:

```powershell
docker compose down -v
```

→ **Rebuild Container**。

### `npm error ... sudo chown -R 1000:1000 "/root/.npm"`

`HOME` が `/root` のまま `node` ユーザーで動いている。`entrypoint.sh` の `export HOME=/home/node` が効いていない = 古いイメージ。**Rebuild Container**。

### `Conflict. The container name "/spfx-dev" is already in use`

`docker-compose.yml` に `container_name:` が固定されている古いテンプレート。行を削除して **Rebuild Container**。
現行テンプレートでは compose がフォルダー名から `<project>-spfx-1` を自動採番する。

## dev server / ワークベンチ系

### `Placeholder {tenantdomain} was found in serve.json but OS variable SPFX_SERVE_TENANT_DOMAIN is not set`

`.env` が未作成、またはコンテナが `.env` 作成前に作られた。

1. プロジェクト直下に `.env` を作成 (`SPFX_SERVE_TENANT_DOMAIN=<テナント>.sharepoint.com`)
2. **ターミナルを閉じて新しく開く** (`load-env.sh` が読み込む)
3. それでも出る場合は **Rebuild Container**

> 手動でワークベンチ URL を組み立てるなら無視しても動作に影響なし。

### ブラウザから `https://localhost:4321` に繋がらない (`ERR_CONNECTION_REFUSED`)

1. serve が動いているか (ターミナルに `Waiting for changes` が出ているか)
2. VS Code 下部「ポート」タブに `4321` が転送されているか
3. コンテナ内で `127.0.0.1:4321` にバインドされているか
   ```bash
   # serve のログに以下が出ていれば OK
   [build:webpack] Started Webpack Dev Server at https://127.0.0.1:4321/
   # https://[::1]:4321/ と出る場合は NODE_OPTIONS の --dns-result-order=ipv4first が効いていない → Rebuild Container
   ```

### ワークベンチで「デバッグ マニフェストを読み込み中にエラーが発生しました」`Script error for "https://localhost:4321/temp/build/manifests.js"`

**原因のほとんどは証明書が信頼されていない**こと。ブラウザは TLS エラーのスクリプトを黙って落とすため、この汎用エラーになる。

切り分け: ブラウザで **直接** `https://localhost:4321/temp/build/manifests.js` を開く。

| 結果 | 対処 |
| ---- | ---- |
| 証明書の警告が出る | `certs\rushstack-serve.cer` を「信頼されたルート証明機関」へインポート → **ブラウザを完全終了して再起動** |
| 接続できない | 上記「繋がらない」を確認 |
| JS が表示される | 証明書 OK。ワークベンチを `Ctrl+F5` で再読み込み |

証明書のインポート方法:

- GUI: `.cer` をダブルクリック → 証明書のインストール → 現在のユーザー (またはローカル コンピューター) → 「証明書をすべて次のストアに配置する」→ **信頼されたルート証明機関**
- PowerShell (管理者): `Import-Certificate -FilePath .\certs\rushstack-serve.cer -CertStoreLocation Cert:\LocalMachine\Root`
- Firefox は Windows ストアを見ないため、Firefox の証明書マネージャーへ別途インポート、または `about:config` → `security.enterprise_roots.enabled = true`

確認コマンド (ホスト側):

```powershell
$f = Get-PfxCertificate .\certs\rushstack-serve.cer
Get-ChildItem Cert:\CurrentUser\Root, Cert:\LocalMachine\Root | Where-Object Thumbprint -eq $f.Thumbprint
# 何も出なければ未インポート
```

> Windows の `curl.exe` (schannel) は `CurrentUser\Root` の証明書を信頼しないことがあるが、ブラウザは信頼するので開発に影響はない。

### ワークベンチに Web パーツが出てこない (ローカル セクションが空)

- serve のビルドが失敗していないか (ターミナルの TypeScript / ESLint エラー)
- URL の `debugManifestsFile` が `https%3A%2F%2Flocalhost%3A4321%2Ftemp%2Fbuild%2Fmanifests.js` と正しくエンコードされているか
- `debug=true&noredir=true` が付いているか

### 複数プロジェクトを同時に開いて serve したら 2 つ目が読み込めない

2 つ目は VS Code が `4322` などにフォワードするが、SPFx のマニフェストは `localhost:4321` を指す。serve は **1 プロジェクトずつ**。
どうしても同時に動かす場合は 2 つ目の `config/serve.json` の `port`・`docker-compose.yml`・`tasks.json`・`devcontainer.json` を別ポートに変更。

## VS Code 系

### `typescript.tsdk` の警告 / 型が解決されない

`.vscode/settings.json` が yo 生成の Windows パス (`.\\node_modules\\typescript\\lib`) になっている。
`node_modules/typescript/lib` に変更 (テンプレートは修正済み)。

### ターミナルで `SPFX_SERVE_TENANT_DOMAIN` が空

- `.env` の場所がプロジェクト直下 (`/usr/app/spfx/.env`) か
- ターミナルが `bash` か (`load-env.sh` は `/etc/bash.bashrc` から読まれる)
- `.env` を編集した後、**新しいターミナル**を開いたか
