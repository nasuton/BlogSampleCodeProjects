# 02. ファイル一覧と変更ポイント

`template/` に含まれる各ファイルの役割と、**新規プロジェクトごとに変更が必要な箇所** をまとめます。

## 変更必要度の凡例

| 記号 | 意味 |
| ---- | ---- |
| 🔴 必須 | プロジェクトごとに必ず変える / 作る |
| 🟡 任意 | 必要に応じて変える |
| ⚪ 不要 | そのままコピーで良い |

---

## 一覧

| ファイル | 変更 | 役割 |
| ---- | ---- | ---- |
| `.env` (`.env.example` からコピー) | 🔴 | `SPFX_SERVE_TENANT_DOMAIN` にテナントドメインを設定。git 管理外 |
| `Dockerfile` | 🟡 | Node 22 + yo + `@microsoft/generator-sharepoint` + heft。SPFx のバージョンを固定したいときに `ARG SPFX_VERSION` を変更 |
| `docker-compose.yml` | 🟡 | ボリューム / ポート / 環境変数。ポートを変えるときのみ |
| `.devcontainer/devcontainer.json` | 🟡 | Dev Containers 本体。拡張機能や `postCreateCommand` を追加したいときに |
| `.devcontainer/docker-compose.devcontainer.yml` | ⚪ | Dev Containers 用オーバーライド |
| `docker/entrypoint.sh` | ⚪ | volume の所有権調整 → `node` ユーザーへ降格 |
| `docker/load-env.sh` | ⚪ | `.env` をシェルに読み込む (CRLF 対応) |
| `docker/serve.sh` | ⚪ | Dev Containers を使わず `docker compose` 単体で dev server を公開するとき用 |
| `docker/trust-dev-cert.sh` | ⚪ | 開発用 HTTPS 証明書を生成し `./certs` へ出力 |
| `.vscode/tasks.json` | 🟡 | serve / build / clean / 証明書タスク。ポート変更時は URL 部分も変更 |
| `.vscode/launch.json` | 🟡 | F5 デバッグ構成。`browserLaunchLocation: "ui"` でホスト側 Edge を起動。Chrome にする / サインイン保持 (`userDataDir`) はここで変更 → [06](06_VSCodeデバッグ手順.md) |
| `.vscode/settings.json` | ⚪ | `typescript.tsdk` をコンテナ内パスに設定 |
| `.dockerignore` | ⚪ | ビルドコンテキストから除外 |
| `.gitattributes` | ⚪ | `*.sh` / `Dockerfile` を LF 固定 |

yo が生成するファイル (`package.json`, `config/*`, `src/*` など) は通常の SPFx と同じで、コンテナ化による追加変更は不要です。
ただし yo 生成の `.vscode/launch.json` はホストにブラウザがある前提のため、テンプレートのものに置き換えます。

---

## 各ファイルの詳細

### `Dockerfile`

```dockerfile
FROM node:22-bookworm-slim          # SPFx 1.21+ は Node 22 必須
ARG SPFX_VERSION=latest             # 🟡 例: 1.23.2 で固定可
ENV NODE_OPTIONS="--max-old-space-size=4096 --dns-result-order=ipv4first"
RUN apt-get install ... socat       # serve.sh 用
RUN npm install -g gulp-cli yo @microsoft/generator-sharepoint@${SPFX_VERSION}
COPY docker/*.sh /usr/local/bin/    # entrypoint / serve / trust-dev-cert / load-env
RUN ... >> /etc/bash.bashrc          # 対話シェルで .env を自動読込
ENTRYPOINT ["entrypoint.sh"]
```

- **`--dns-result-order=ipv4first` は必須**。これが無いと dev server が `[::1]:4321` (IPv6) にだけバインドし、VS Code のポートフォワード (IPv4 `127.0.0.1` 経由) が `ECONNREFUSED` になる。
- `image:` / `container_name:` は compose 側で **固定しない**。固定すると 2 つ目のプロジェクトが `Conflict. The container name "/spfx-dev" is already in use` で起動できない。

### `docker-compose.yml`

```yaml
services:
  spfx:
    build: { context: ., dockerfile: Dockerfile }
    working_dir: /usr/app/spfx
    volumes:
      - ./:/usr/app/spfx                          # ソースはホストをマウント
      - spfx_node_modules:/usr/app/spfx/node_modules  # 名前付き volume (高速・OS差異回避)
      - spfx_rushstack:/home/node/.rushstack      # 証明書を永続化
    ports: ["4321:4321"]                          # Dev Containers 時はオーバーライドで解除
    environment:
      - NODE_OPTIONS=--max-old-space-size=4096 --dns-result-order=ipv4first
      - SPFX_SERVE_TENANT_DOMAIN=${SPFX_SERVE_TENANT_DOMAIN:-}   # .env から
```

- 名前付き volume 名は compose がプロジェクト (フォルダー) 名でプレフィックスするため、プロジェクト間で衝突しない。
- 🟡 ポートを変える場合: ここ・`config/serve.json` の `port`・`.vscode/tasks.json` の URL・`devcontainer.json` の `forwardPorts` の 4 箇所。

### `.devcontainer/devcontainer.json`

```jsonc
{
  "dockerComposeFile": ["../docker-compose.yml", "docker-compose.devcontainer.yml"],
  "service": "spfx",
  "workspaceFolder": "/usr/app/spfx",
  "remoteUser": "node",
  "shutdownAction": "stopCompose",
  "forwardPorts": [4321],
  "postCreateCommand": "npm install && trust-dev-cert.sh",   // 🟡 追加の初期化があればここ
  "customizations": { "vscode": { "extensions": [ /* 🟡 */ ], "settings": { ... } } }
}
```

### `.devcontainer/docker-compose.devcontainer.yml`

```yaml
services:
  spfx:
    ports: !reset []        # VS Code がフォワードするので docker 側の公開は解除
    command: sleep infinity # VS Code Server 接続のため常駐
```

### `docker/entrypoint.sh`

名前付き volume は初回作成時 root 所有になるため、root で起動 → `node_modules` と `~/.rushstack` を `chown node` → `HOME=/home/node` を設定 → `setpriv` で `node` ユーザーに降格して本来のコマンドを実行する。

### `docker/load-env.sh`

`/usr/app/spfx/.env` を `set -a` で読み込む。Windows で編集された CRLF の `\r` を除去し、コメント・空行を無視。
`/etc/bash.bashrc` (対話ターミナル)・`tasks.json` の serve タスク・`serve.sh` から呼ばれるため、
**`.env` を変更してもコンテナ再作成不要** (新しいターミナルを開くだけ)。

### `docker/trust-dev-cert.sh`

`heft trust-dev-cert` で `~/.rushstack/rushstack-serve.pem` を生成し、`./certs/rushstack-serve.cer` にコピー。
Linux コンテナ内では OS への信頼登録ができないため、**ホスト側で手動インポート**が必要。
証明書は volume に永続化されるので、コンテナを再作成しても同じ証明書が使われる (インポートは 1 回で済む)。

### `docker/serve.sh`

Dev Containers を使わず `docker compose run --rm --service-ports spfx serve.sh` で起動するとき用。
SPFx の dev server は `localhost` にしかバインドせず、かつその値がマニフェスト URL にも使われるため `0.0.0.0` にできない。
そこで `socat` でコンテナ NIC の 4321 → ループバックへ転送してホストから到達可能にする。**Dev Containers 環境では不要**。

### `.vscode/tasks.json`

| タスク | コマンド |
| ---- | ---- |
| `SPFx: serve` (既定ビルドタスク `Ctrl+Shift+B`) | `.env` 読込 → Workbench URL 表示 → `npx heft start --clean --nobrowser` |
| `SPFx: build (production)` | `npm run build` → `sharepoint/solution/*.sppkg` |
| `SPFx: clean` | `npm run clean` |
| `SPFx: trust dev cert` | `trust-dev-cert.sh` |

### `.vscode/settings.json`

yo が生成する `"typescript.tsdk": ".\\node_modules\\typescript\\lib"` (Windows パス) をコンテナ内で解決できる `node_modules/typescript/lib` に変更済み。

### `.gitignore` への追記 (yo 生成物に追加)

```
# Docker / local
.env
certs/
```
